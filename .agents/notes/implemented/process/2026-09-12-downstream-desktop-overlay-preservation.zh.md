# Agent Note: Preserve downstream Desktop behavior across upstream updates

Status: implemented

[English](2026-09-12-downstream-desktop-overlay-preservation.md) | 中文

## Problem

个人 Desktop 发行版跟随 DeepSeek Harness 上游发布，同时保留上游不负责的用户可见行为和文档。上游合并可能把共享文件直接解析为上游版本，而构建仍然成功，从而静默删除下游应用图标、版本展示、更新历史、来源说明或本地安装插件的激活状态。因此，编译成功不能证明个人发行版在更新后仍保持完整。

## Decision

每次 Desktop 上游更新都先清点下游专属提交、源码路径、已安装 profile 包和可观察的用户行为。合并完成后，维护者把结果与合并提交的第一父提交进行比较，并将每项删除分类为通过适配保留、由明确验证过的上游机制替代，或作为具名回退延期处理。只有根目录双语 Desktop 历史、打包应用图标、紧凑侧栏版本徽标、已安装外部插件依赖图和共享用户数据都有直接证据后，才可以部署。

仓库测试固定根目录中英文 Desktop 章节、electron-builder 图标配置和侧栏徽标行为。运行时验证检查已安装应用的版本与图标，启动随包 Host，检查保留的 Desktop profile 中精确的插件依赖图，并确认共享 Session 仍然可见。窗口装饰、托盘生命周期、重启规则、日志和本地未签名打包等发生架构变化的功能，必须明确决定保留或替代，不能从文件是否存在推断结论。

## Alternatives considered

**所有合并冲突都接受上游版本，再补回肉眼可见的差异。** 这种方式容易通过编译，但会把未经检查的删除当成有效解决方案，也会漏掉只有安装后才能发现的功能。

**依赖 Git 历史和人工记忆。** 被删除的工作仍可恢复，但两者都不能在部署前让更新失败，细小的展示和 profile 差异尤其容易遗漏。

**为完整 Desktop 目录维护长期补丁文件。** 整个目录的补丁会阻碍上游架构改进，并造成巨大且脆弱的冲突。清单与聚焦检查既保留预期结果，又允许实现发生变化。

## Consequences

- 上游更新除了构建和打包验证，还必须经过下游特征保留阶段。
- 删除个人版特征必须有明确记录的处理结论，不能成为隐含的合并结果。
- 根目录 Desktop 历史、品牌应用图标与紧凑版本徽标在上游同步丢失时，会导致聚焦测试失败。
- 已安装第三方插件和共享数据属于部署证据，因为它们是用户状态，不是仓库测试夹具。
- 如果能够证明用户结果相同或更好，审计可以保留新的上游机制，而不携带过时的实现文件。
